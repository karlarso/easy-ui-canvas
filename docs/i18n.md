# Language support (English / Chinese)

Everything user-facing exists in English and Chinese: the list page, the agent guide on the list (`/agent` and `/agent.md`), the canvas page and its dynamic text, toasts and errors, the phone preview, the shortcuts dialog, the labels of the "Design notes" dialog (the `DESIGN.md` text itself is the project's own and is shown as written), the text copied by "Copy this comment" and "Copy for AI" (`c.fbHead` / `c.fbRow`; the button label is `c.copyComment`; comment fields are copied as stored), the text copied by "Copy frame reference" (`c.ref.*`; frame ids, titles and links are copied as they are), error messages returned by the server, the CLI output, the UI-handoff export (`HANDOFF.md`, `index.html`) and the example projects (`examples/en`, `examples/zh`).

## How it works

- **One dictionary**, `assets/i18n.json`: `{ "zh": {key: text}, "en": {key: text} }`. Placeholders look like `{name}`. No third-party library.
- **Browser**: the server inlines the dictionary and the active language into each page (`window.UIC_DICT`, `window.UIC_LANG`); `assets/i18n.js` provides `tr(key, {name: value})`, `data-i18n="key"` for element text and `data-i18n-<attribute>="key"` for attributes. The English text is also baked into the HTML as the fallback.
- **Server and CLI**: `canvas.py` has the same `tr()` and reads the same file.
- **Storage is server-side and global**: the choice is saved in `<runtime>/config/lang.json`, which the list service, every canvas process and the CLI read. Browser storage (localStorage) is per origin, so it would not be shared between the list page (port 4042) and canvases (other ports); a server-side file is. The language switch on the list page (`Auto / 中文 / English`) calls `POST /api/lang`; open canvas pages and the phone preview pick the change up when they regain focus (not while a dialog is open or an input is focused).
- **Default** (nothing stored, "Auto"): follows `navigator.language` in the browser (`zh*` → Chinese, anything else → English) and `Accept-Language` on the server.
- **Per request**, API errors use: the `X-UIC-Lang` header (the page's fetch wrapper adds it, so errors always match what the page shows) > the stored language > `Accept-Language`.
- **CLI**: `$UI_CANVAS_LANG` > stored language > `$LC_ALL` / `$LC_MESSAGES` / `$LANG` > English. `canvas.py lang [zh|en|auto]` shows or sets the stored language.
- `POST /api/lang` accepts same-origin requests (or requests without an `Origin` header, such as the CLI/curl) only.

## Adding or changing text

1. Add the key to both `zh` and `en` in `assets/i18n.json` (same placeholders in both).
2. Use `tr('key')` in JS/Python or `data-i18n` in HTML (keep the English text as the HTML fallback).
3. Run `python3 tests/test_i18n.py`: it checks that both languages have the same keys and placeholders, that every key used in code exists, that no key is unused, that the HTML fallback equals the English text, and that Chinese characters appear only in the zh dictionary, `assets/agent.zh.md`, `README.zh-CN.md`, `DEPLOY.zh-CN.md` and `examples/zh/` (plus the bilingual docs called out in the test).

To add a language, add a third top-level object to the dictionary, extend the language list in `canvas.py` (`LANGS`) and the selector in `assets/list.html`, and relax the alignment test accordingly.
